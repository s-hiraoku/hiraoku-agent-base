# Review method and limits

Five read-only source readers partitioned the initial 122 discovered documents: foundations16, authority16, delivery18, execution28, verification44. Included first-party documents were read in full; vendored security methodology16 was separately indexed and excluded after scope/provenance review. Exact source citations were byte/hash-validated by the coordinator. Each candidate was reviewed for rationale, scope, decision and checks. No source reader drove a service; the coordinator owns all live driving.

[source-review.json](source-review.json) records supplemental source ranges and full/partial status, including TypeScript/JavaScript entrypoints, SQL/schema, configuration examples, package scripts and the optional Python bridge/bootstrap/token helpers. This is a trace ledger, not a claim every line of every implementation file was read. The CLI auto-discovers tracked/unignored Markdown/MDX/RST/AsciiDoc/txt plus non-image/non-PDF assets under docs. It does not automatically classify arbitrary TS/SQL/config paths outside docs; those were inspected as supplemental evidence. Images/PDF/wiki/issues/ignored/private locations were not used as unexamined authority. Mermaid source and generation manifest, not PNG pixels, supply diagram intent. No production configs or private histories were read.

[external-references.json](external-references.json) preserves every source-reader external-link occurrence, revision and access outcome. Duplicate occurrences are deliberate provenance. Most were not fetched; some delivery references were opened only to initial excerpts. Full remote/revision review remains pending, including external standards/current issue/host behavior. No current external guarantee is inferred from those links; authoritative extracted requirements cite local adopted design. External compatibility/security/price/capability claims remain manual.

The source fixture already has native TS typechecking and JavaScript behavior tests. The contract additionally checks real child-process SQLite failure boundaries, AST negative/harmless controls and a model-free actual loopback MCP/HTTP + independent SQLite path. Existing Python bridge tests are included only for the Python implementation they exercise. The external hirastack coordinator being Python creates no Python-only product verification assumption and proves no behavior for an untested language.

Evidence boundaries: raw poll/ACK is wire-only; before-network ACK durable proof requires an independent read-only connection seeing committed body and exact pending ACK journal. The real helper uses synthetic authority and existing verification scaffold. The existing common-MCP suite uses actual HTTP and SQLite with injected two-cycle scheduler/Task policy. F05 uses actual isolated child SIGKILL after its saved marker with injected poll/ACK ports. Journey/restart fixture and the helper recipient reopen are orderly, not crash tests. None proves power-loss, physical media, full fleet restore, real native agent input/display/model/tools/approval or wall-clock resident polling.

Manual feature UI/native/operational work is unverified even when tests overlap that feature.

## PR141 correction: bounded saved reads and parent-owned stdio cleanup

Reviewed the completed correction diff against `3f1ffd61d3abbedbbc376d221465ce7772dd7d42`. This is an implementation/verification correction, not a design-authority change. All existing requirement statements, rationales, scopes, decisions and manual checks are preserved. The proposal stays context and existing feature recipes remain authoritative.

The wrapper's owner-only `maxInboxReadResultBytes` defaults to 1 MiB and must be a safe integer of at least 1 KiB. It measures the serialized inbox_read CallToolResult after current host authorization, with UTF-8 and nested JSON escaping. Oversize returns only a fixed error plus the required byte count; it does not consume the source, return a partial body, retry, or replace mutating-operation results. This is not a whole-wire or serialization-memory cap: JSON-RPC framing, request IDs and other results remain transport-composition responsibilities. A compatible owner-configured server/client pair can reread the complete same source under current authority; an incompatible product stays blocked. No automatic budget expansion, paging or native authority is introduced.

The real-host stdio test now places broker and temporary-directory ownership in the test parent, outside the killable fixture child. The parent awaits stderr end before evaluating the child marker and independently stops the broker/removes scratch even after deliberately blocked child cleanup. The new fault case verifies absent clean-child success, removed scratch and an unreachable owned broker port. It does not claim kill9 durability or normal child shutdown.
