# Local ingress and outcome controls

This source change preserves fixed task schemas, verified issuer/subject/client policy, the authoritative durable stop gates, fenced leases, request idempotency and transactional task/outbox audit. It does not configure Auth0, replace a route, restart a service, create credentials, send external alerts, or enable a new task/worker.

The Node server initializes a private `runtime/audit` directory before listening. Every admitted HTTP exchange receives a fresh opaque request ID; tool invocation and success/error are recorded separately, including errors carried in an HTTP 200 MCP response. The local log records only UTC time, a fixed enum category and this ID. It never records tokens, principals, arguments/results, raw URL/task/session IDs, forwarding IP, or stack traces. Three files at most, 256 KiB each; archived files older than 24 hours are removed on activity. Twenty errors/rejections per minute create a local anomaly category. No external notification occurs. Disk/permission/symlink failures deny admission/action. A post-action audit failure cannot roll back an already committed operation; the existing transactional task audit remains the authority and idempotent requests must be reconciled before retry.

HTTP admission is capped at 120 requests per minute and four active exchanges; tool starts at 60 per minute. Counters use fixed global buckets, never attacker-supplied IP/token/session labels, and reset on restart. Native headers are limited to 16 KiB; JSON bodies to 32 KiB with a five-second body-read deadline. The native server also has finite request/header deadlines. Task insertion checks 128 active rows and 10,000 total retained rows inside the same authorized SQL batch. Existing request keys remain replayable at capacity; cancellation can free active capacity. There is no automatic record deletion: reaching the retained-row ceiling requires separately reviewed export/retention work, preserving audit evidence. These are operational bounds, not a durable billing guarantee.

Portable runtime callers may provide an `AuditSink`; Node filesystem logging is never imported into the worker bundle. The supplied Node entrypoint uses required filesystem logging. Direct library callers are responsible for supplying their own security context/sink; the deny-all worker entrypoint remains deny-all. The local audit is separate from task transitions and does not change existing outbox delivery semantics.

Host/Origin and duplicate-header checks remain authoritative. Forwarded-IP headers are ignored; rate limits do not assume a trusted Funnel proxy. Actual proxy header preservation, production authentication and the deployed image are unverified. Auth0 migration of the model MCP is documented in its own repository and must use a separate resource audience. Existing OS isolation is unverified. Deployment, credentials/scopes, route changes, process restart and paid-model budget require separate approval; this PR grants none.
