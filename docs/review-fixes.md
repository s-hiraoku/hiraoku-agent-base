## Bounded audit semantics

The default Node server uses one isolated writer with an empty environment and at most 32 pending acknowledged entries (hard configurable ceiling 64). Request/task execution waits for its before-action audit ACK. A five-second startup/ACK deadline, worker exit or write failure latches the process unavailable; pending/future actions fail closed, with no automatic writer retry/restart. Queue overflow rejects before action. Failed after-action audit cannot undo an already committed task; reconcile using the existing durable task audit/idempotency before retry.

At most 120 HTTP requests/minute enter detailed processing, four at once; at most 60 tool starts/minute. Rejection counters use a fixed category map, saturate at 65,535 and produce at most one summary per ten seconds. Summary fields are fixed category counts, dropped lower-bound count, saturation and anomaly flags (20 suppressed events). No token, principal, argument/result, raw URL/task/session ID, forwarding IP or stack appears. Unacknowledged summary counts remain bounded in memory and are not automatically replayed. Crash/restart may lose the last unflushed counters; ACK is an OS write acknowledgement rather than fsync. Three private log files at most, 256 KiB each, with fixed-name rotation/retention checks; filesystem work does not run on the HTTP event loop.

Unknown pending tool work retains admission until its per-invocation ticket settles, even if the client response closes or hits a deadline. A response timeout never proves the underlying task stopped. Short fixed metadata/discovery exchanges are permitted; SDK stream subscriptions are neither advertised nor dispatched. Outbox webhook subscriptions remain their separate explicitly authorized API, with no listener stream enabled.

## ACK-wait disconnect and SDK outcome follow-up

The old `4acd0c7` native lifecycle was reproduced with four real local HTTP sockets disconnected while the request audit ACK was delayed: zero slots could be re-admitted after ACK. Admission now binds response finish/close cleanup before awaiting the audit record. Closure is checked again after ACK, so disconnected requests cannot authenticate or dispatch. The regression proves all four slots recover both before and after ACK and no task is inserted; live/pending tool tickets still use idempotent deferred release.

`protocol-boundary.test.js` also covers SDK-generated media-type (415), unsupported version, malformed envelope and Accept/header rejection through native and portable paths. SDK responses with status 400 or greater add fixed `transport_error` without saving headers, versions, body or error text. This complements pre-callback tool/schema classification rather than depending on callbacks for protocol failures.
