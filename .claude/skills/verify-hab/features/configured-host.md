# Configured host and operator CLI

The shipped host (`npm run hab:host -- --config …`) refuses a bad start with a fixed reason line, and the operator CLI (`npm run hab:admin -- --config … status|connect|disconnect|rename|receive|session`; `rename` is driven in [resolve-address.md](./resolve-address.md)) registers an address, binds a mapped connection, grants operations and revokes it again — all against the same private config while the host runs. This is the path a real Codex ⇄ Hermes trial uses, unlike the `stack.mjs` scaffolding.

## Sub-features

- `start-reason` a refused start prints `host_start_rejected reason=<code>[ fields=<paths>]` (e.g. missing `delivery.queue.agent_capacity` → `reason=config_invalid fields=delivery.queue.agent_capacity`), never values or paths.
- `retired-config` a config that still has the retired SQLite `store` section (and no `delivery`) is refused with `reason=config_invalid fields=delivery,store` before any state is created.
- `admin-connect` `connect --address <a> --connection-id <id>` registers product/address, creates the connection's authentication group (the address is its only member), binds and grants; rerun returns `steps: []`.
- `admin-receive` `receive --agent-name <product> --mode hook|poll|on_request [--interval-ms <60000..86400000>] --request-id <id>` sets how a product hears about new mail (ADR-032). `interval_ms` goes only with `poll`; anything else is `invalid_registry_request`, an unknown product `registry_not_found`. `status.products[]` shows `{agent_name, receive}` (`receive: null` until set).
- `admin-session` `session --address <a> --session <name> [--replace true] --request-id <id>` names the product session the address stands for. Every address starts as a provisional session named after itself (`session.provisional: true`); a named one is not replaced without `--replace true` (`registry_session_bound`), and two addresses of one product never share a name (`registry_session_taken`). Provisional names are not unique, so an operator name never blocks a later address from enrolling. A registry from before ADR-032 makes `status` answer `registry_upgrade_pending` until the host starts once.
- `admin-status` `status` lists addresses, credential lifetime/audience/binding and `problems` (`credential_unbound`, `credential_expired`, `credential_audience_mismatch`, `credential_revoked`, `address_unbound`, `address_stopped`). Since ADR-024 it also lists `inboxes[]` per active address (`unread`, `oldest_unread_at`, `doorbell` live/lapsed/none/off) with `unread_waiting` (unread ≥ 30 min) and `doorbell_lapsed` problems, plus `doorbell_last_rang_at`/`doorbell_last_status`/`doorbell_last_delivered_at` and a `doorbell_failing` problem once a recipient has been rung. `configured.sh` writes no `ingress`, so `doorbell` is always `off` there and `unread_waiting` is out of reach within the credentials' 15 minutes; the live check is `unread: 1` with an `oldest_unread_at` for a submitted, unpolled message. Status also lists other problems (`participation_*`, `group_<state>`, `config_previous_address*`, `emergency_stopped`) not driven here.
- `admin-disconnect` `disconnect --address <a>` revokes with current epochs; works after the token mapping was deleted; rerun → `already_disconnected: true`; the old token then gets `forbidden`.
- `group-disconnect` disconnecting one member of a shared connection stops **every** member (`state: stopped`, `operations: []`) and lists them in `affected_addresses`. Reconnecting one address with a new connection id re-grants only that address; its sibling stays `stopped` and polling as it is `forbidden`. A poll without `as_address` selects the only active member.
- `admin-refusals` `connect … --operations ""` → `admin_rejected invalid_operations`; a group connect refused by binding capacity creates no group (a retry converges); a config that still says `registry.authentication_groups: false` connects through a group all the same; a registry an earlier build left with direct bindings is refused with `registry_upgrade_pending` until the host starts once.
- `registry-limits` an out-of-range `registry.*` limit (e.g. `busy_timeout_ms` above 1000) is refused at start with `reason=config_invalid fields=registry.<field>`.
- `configured-roundtrip` a → b submit / poll / ack / sender status `acked` through the shipped host and its SQLite delivery store. A submit with an `attachment` part is refused (`isError`, nothing stored), as in `send-attachment-refused`.
- `host-exact` `Host: localhost:<port>` → HTTP 403; only `127.0.0.1:<port>` is accepted.

## How to get to it (user POV)

- Operator shell: `npm run hab:host -- --config <service.local.json>` and `npm run hab:admin -- --config <service.local.json> <command>`.
- Agents: each agent's MCP client at `http://127.0.0.1:<port>/mcp` with its own bearer.

## Driving it with verify-hab

Preconditions:

- `npm ci` with Node ≥ 26. A fresh `RUN=/tmp/hab-verify/<id>` (do not reuse a stack.mjs run dir).

- **Start.** `$S/configured.sh "$RUN" start` writes example-based config, random keys and two synthetic 15-minute credentials under `$RUN/instance/`, fills `delivery.volume` for `instance/state`, starts `scripts/hab-host.ts`, runs `hab:admin connect` for `a` = `codex@codex.hab` and `b` = `hermes@hermes.hab`, and prints `CONFIGURED_READY <url>`. `instance/state.json` has the same shape as the stack's, so `mcp.sh` and `new-message.sh` work unchanged. Connect output is saved as `evidence/admin-connect-{a,b}.json` (`steps` lists what was created).
- **Roundtrip.** Use the minimal round trip from `SKILL.md` with agents `a` and `b` (target `hermes@hermes.hab`). Sender `hab_status` ends `"acked"`. `instance/state/` holds `delivery.sqlite` and no `relay.sqlite` or `jetstream-journal.sqlite`.
- **Status.** `$S/configured.sh "$RUN" admin status` → `problems: []` while both are connected. Between the submit and the poll of the roundtrip, `jq '.inboxes'` shows `hermes@hermes.hab` with `unread: 1`, an `oldest_unread_at` and `doorbell: "off"`.
- **Receive and session.** `$S/configured.sh "$RUN" admin receive --agent-name hermes --mode poll --interval-ms 60000 --request-id r1` → `receive.mode: "poll"`, `interval_ms: 60000`. `$S/configured.sh "$RUN" admin session --address hermes@hermes.hab --session desk --request-id s1` → `session.provisional: false`. `admin status` shows both under `products[]` and the address's `session`; a second `session … --session other --request-id s2` answers `admin_rejected registry_session_bound`.
- **Disconnect.** `$S/configured.sh "$RUN" admin disconnect --address hermes@hermes.hab` → `revoked_bindings: 1`; again → `already_disconnected: true`; `$S/mcp.sh "$RUN" b hab_poll '{}'` → `{"error":"forbidden"}`; `status` shows `credential_revoked` and `address_stopped`.
- **Group disconnect.** Start a separate run with `HAB_VERIFY_GROUPS=1 $S/configured.sh "$RUN" start`: `state.json` has an unconnected spare credential `c` (`.agents.c.connection_id`). Read `a`'s connection id from `admin status` (`.credentials[] | select(.addresses == ["codex@codex.hab"]) | .connection_id`), then `admin connect --address second@codex.hab --connection-id <it>` → `steps: [address_enrolled, group_member_added, address_access_granted]`. `admin disconnect --address second@codex.hab` → `affected_addresses` both, and `admin status` shows both `stopped` with `operations: []`. `admin connect --address codex@codex.hab --connection-id <c's id>` → `steps: [connection_bound, group_access_granted, address_access_granted]`; then `$S/mcp.sh "$RUN" c hab_poll '{"as_address":"second@codex.hab"}'` → `forbidden`, `as_address` codex and an empty selector → `{"delivery":null}`.
- **Start reason.** Copy `instance/service.local.json` to `instance/bad.local.json` (0600) with `delivery.queue.agent_capacity` removed and run `node scripts/hab-host.ts --config "$RUN/instance/bad.local.json"`: exit 1, the single stderr line above.
- **Legacy journal.** Stop, `touch instance/state/jetstream-journal.sqlite` (0600) and start again with `node scripts/hab-host.ts --config "$RUN/instance/service.local.json"`: exit 1, `host_start_rejected reason=legacy_jetstream_journal_present`. Remove the file before continuing. A config with `delivery.broker` or `delivery.pump` is refused with `reason=config_invalid fields=delivery.broker` (or `delivery.pump`).
- **Retired config.** `jq '.store = .delivery.queue | del(.delivery) | .port = 0' instance/service.local.json > instance/old.local.json` (0600), then start with it: exit 1, `host_start_rejected reason=config_invalid fields=delivery,store`.
- **Host.** `curl -s -o /dev/null -w '%{http_code}' -H "Host: localhost:<port>" -H "Authorization: Bearer $(jq -r .agents.a.token "$RUN/instance/state.json")" -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' "$(jq -r .url "$RUN/instance/state.json")" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'` → `403`.
- **Stop.** `$S/configured.sh "$RUN" stop` stops the host (by pid + cmdline) and prints `stopped <pid>`. It leaves `$RUN/instance`; run `rm -rf "$RUN/instance"` yourself afterwards. `evidence/host.log` keeps `ready`/`stopped`.

## Gotchas

- `inspect.mjs` and `doctor.sh`/`cleanup.sh` target the stack layout; use `configured.sh … admin status` and `configured.sh … stop` here.
- An accepted message is pollable at once; `{"delivery":null}` right after a submit means the recipient already holds a lease or the message is not addressed to it.
- If `start` fails after the host came up, run `configured.sh "$RUN" stop` anyway.
- Credentials expire 15 minutes after `start`; after that every call is 401 and `status` shows `credential_expired`. Relaunch with a new run dir.
- A group stop or its last disconnect stops every member; reconnect each member address you still want (one `connect` per address).
- A revoked connection id can never be bound again (`credential_revoked_use_new_connection_id`); a new credential needs a new `connection_id`.
- `limits` no longer has `attachment_bytes`, `total_attachment_bytes` or `attachments`. A config that still carries any of them is refused at start with `reason=config_invalid` and `fields=` listing each unrecognized key (for example `limits.attachment_bytes`, or all three sorted). Delete those keys.
- Tokens are synthetic and local; a pass is not evidence of a real Codex/Hermes client or model choosing tools.
